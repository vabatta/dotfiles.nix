# Report

Read-only on the source. The report comes from the trail, the plan, and the diff, never from memory of the conversation.

1. Fix the base per the fixed point rule in **accept-change**. Done when `git diff --stat <base>` is non-empty, or the reply says that nothing changed.
2. Gather the claims: the trail in `.agent/decisions/` per **show-me-your-work**, the plan or contract under `.agent/runs/`, and any handoff in `.agent/handoffs/`. Treat each as a claim to check against the diff. Done when every claim has a source.
3. Re-verify the done predicate and each landed unit on the real artifact per **principle-prove-it-works**. Give each a status of VERIFIED, NOT VERIFIED, or INCONCLUSIVE with evidence. Done when none lacks a status.
4. Write `.agent/runs/report/<slug>.json` in the shape of [example.json](references/example.json). Order the walkthrough steps for comprehension: definitions before their consumers, wiring after the parts it joins, tests beside their subjects. Put every changed file outside `.agent/` in exactly one step. Give each step one summary sentence and 2 to 6 short change bullets that name real identifiers. Give the report 3 to 5 highlights. Add 1 to 3 `diagrams` when a flow or a lifecycle is easier to see than to read, each one concern, written per **mermaid**. Add 2 to 6 follow-up prompts under `next`, each with a title, one why sentence, and a prompt that starts with the `/skill` to run and names real paths. State each input and leave out what the skill already does. Write all text per **simple-english** in pragmatic mode and **technical-writing**: sentences of 25 words or fewer, no should, may, or could, and one name for each thing. Set each decision's confidence to high when step 3 re-verified its evidence, low when it rests on a claim alone, and medium otherwise. Add a `confidence_why` sentence that names the evidence behind the level. Done when the file matches the example's keys.
5. Render from the repo root with `python3 <this skill's directory>/scripts/render.py .agent/runs/report/<slug>.json .agent/runs/report/<slug>.html`. The renderer reads the patches from git, sorts decisions least-confident first, and rejects a step list that misses or repeats a changed file. It counts files under `.agent/` but leaves them out of the walkthrough. It warns on stderr about any sentence over 25 words and any should, would, could, may, might, has been, have been, n't, or semicolon. It parses each diagram with `validate-mermaid` and fails on one that does not parse. It warns about a `/name` in a follow-up that matches no skill folder. Fix the data on an error or a warning and never bypass the renderer. It shows untracked files as new files without touching your index. Done when it exits 0 with no style warnings.
6. Reply with the html path, the status counts, the three least-confident decisions, what is open, and how many untracked files it shows as new. Open the page when a browser exists.
