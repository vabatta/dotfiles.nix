# Understand code

**Pick when:** the goal is knowledge, not a change: where does this live, how does it work, why is it this way, explain it.
**Chain:** how, why, teach
**Journey:** no
**Done looks like:** the answer, with file:line references a reader can check.

## Steps
1. **how** for where it lives and how data flows.
2. **why**, only when the question is about a reason or past decision.
3. **teach**, only when the user wants to understand it, not just locate it. It reuses the how and why output.

## Watch for
- Changing code while explaining it. This playbook writes nothing.
