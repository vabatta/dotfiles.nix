The idea

Skills load on demand. The host reads the one-line description of each skill and loads the one that matches. The description alone decides the trigger. You call most skills as entry points. Other skills run the building blocks. There are four layers: the always-on rules, the journeys, and two kinds of skill.

Rules

Always on

Six global rules load in every session in Claude Code and opencode. They apply to everything below and need no trigger. Each rule names a skill that the agent then loads.

Journeys

Start here for a situation

A named entry point for one real situation. It sets where you start.

Process

One workflow, several skills

A named phase that puts other skills in order: design, plan, review, debug. Run it directly, or let a journey call it.

One-shot

One skill, one job

A single invocation that produces one thing: a trace, a verdict, a diagram, or a fix.

Global rules always loaded, in every session

    Where things live the code is the truth, memory holds the rest

    The code is the source of truth: behavior lives in test names and types. What code cannot say goes to a gm note, anchored to the code it concerns. Almost nothing is written to files. The glossary lives under docs/, and everything else a skill writes under .agents/.

    Journeys start from your situation. Each step names the skill to call.

    A journey is a preset entry point for one real situation. Journeys are grouped by family, and you can add more. Open one to see when to use it and its steps. To start, call the first skill by name, for example /build. When it finishes, come back for the next step and call that skill. A step lists only the skills that you call. Between the skills in one step, then means in order, or means pick one, and + means do both. A uses line shows the building blocks that the step runs for you. A branch line says when to do a step or skip it. The global rules above apply to every step: state the stack and the budget, verify the real artifact, continue on reversible work, and keep the trail. A done line says only what the steps produce. Nothing runs the journey for you.

    Process skills named workflows. Run them directly or from a journey.

    One-shot skills one purpose, one invocation

    A card with a grey edge is a building block. Other skills run it. Call it directly only for its narrow task.
